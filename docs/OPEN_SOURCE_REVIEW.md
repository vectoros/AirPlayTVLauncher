## 发布 GitHub 前优先完成

### 隐私与历史

- 决定是否允许现有作者邮箱、截图中的城市与应用列表公开。不要仅修改当前文件后误以为历史也已清理。
- 如需隐藏作者邮箱，先配置 GitHub noreply 身份用于后续提交；既有作者与提交者字段需要单独处理历史。`.mailmap` 只改变部分显示方式，不移除原始元数据。
- 如需清除旧截图或其他敏感内容，在首次推送前备份并重写相关历史，检查所有拟发布分支和标签。历史重写会改变提交 SHA，本次没有执行。
- 发布前用专用秘密扫描器再扫描完整历史，包含拟发布子模块；如发现真实凭据，先撤销或轮换再清理。参考 [GitHub 的敏感数据移除说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。

### 许可与发布物

- Launcher 自有代码为 MIT；接收端及其补丁遵循上游 GPL。发布页面和下载附件分别标注许可，保留版权与第三方声明。
- 若发布 AirPlay APK，准备与所发二进制匹配的完整对应源码、补丁、构建脚本和依赖许可材料，并核对 UxPlay、FFmpeg、OpenSSL、libplist 等依赖的具体版本及构建选项。仅提供上游首页链接不足以说明如何重建所发版本。
- 当前接收端脚本使用经 SHA-256 校验的 F-Droid APK 内原生库，再构建修改后的 Android 层，主要覆盖 armv7。原生库从源码重建及对应依赖归档仍需验证；不要称为已完成全源码可复现构建。
- Google APK、调试日志、个人照片和系统固件不应混入项目发行包。截图中的第三方名称和图标仍属于相应权利人。

### 构建、签名与供应链

- 在干净环境验证 Launcher 和 AirPlay 接收端构建；当前 CI 只覆盖 Launcher 的构建、测试 APK 编译与 lint，没有执行真机 instrumentation 测试或构建接收端。
- 补充 Gradle 分发包校验摘要，验证 Wrapper JAR 来源；将第三方 GitHub Actions 固定到经核验的完整 commit SHA，并建立更新方式。参见 [GitHub Actions 安全使用说明](https://docs.github.com/en/actions/reference/security/secure-use)。
- 发布使用受保护的 release 签名，不能依赖开发机 debug keystore。Launcher 与接收端的 signature 权限要求签名匹配，需要同一受控签名方案和更新策略；私钥不得进入仓库。
- 当前 `main` 停留在初始版本；需将完成的功能分支纳入发布分支，检查子模块引用，再创建版本标签。审查时未配置 Git remote，本次未推送或创建 GitHub 仓库。

### 产品与维护

- AirPlay 当前自动启动、PIN 默认关闭。公开发行前建议提供明确的启停设置和持久停用选项，并验证 PIN 保护；与现有电视的自动启动需求分别处理。
- 完成真实 Apple 设备投屏、音视频同步、休眠重连、接收端重启、低内存及长期运行测试。保持“非完整 AirPlay 2、DRM 不支持”的现有说明，避免夸大兼容性。
- 补齐 Android 8–11 与不同 ABI 的测试矩阵，验证遥控器、照片读取、权限拒绝和天气网络失败。已编译不等于已在各平台通过运行验证。
- 添加 SECURITY.md、贡献指南和问题模板；提供英文说明、隐私说明及可配置的应用排序，便于其他地区和设备使用。
- 保持天气提供商署名及用途限制说明，商业使用前重新确认 API 服务条款。照片本地存储与 IP 定位的数据流应在设置或说明中容易找到。
