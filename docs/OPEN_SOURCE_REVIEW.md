## Git 历史状态

删除当前文件不能移除旧提交。已在隔离副本中完成历史清理并复核：移除相关截图的全部版本、清理早期默认位置与测试文案、替换个人邮箱，保留提交顺序和上游子模块引用。

本次清理发布经维护者明确授权，用清理后的版本替换 GitHub main 的 9 个旧提交，并新增文件清理记录。仅更新 main，采用指定旧提交的 `--force-with-lease` 防止覆盖并发修改。历史更新会改变项目提交 SHA，协作者需要重新克隆或正确迁移分支，不能再合并旧历史。

即使更新远端引用，旧提交也可能仍存在于其他克隆、fork 或 GitHub 的缓存视图中。需要时按 [GitHub 敏感数据移除说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository) 处理残留；本次没有向其他人或 GitHub Support 发送消息。

清理候选历史的扫描、文档链接及 Git 对象完整性检查通过；当前 Launcher、接收端补丁和上游子模块版本与清理前一致。清理前备份仅在本地忽略目录中保留。

## 运行时数据边界

天气功能在运行时处理公网 IP 和城市级坐标，保留 [数据流说明](../README.md#数据隐私与许可)。相册副本、天气缓存和城市选择存于电视本机，不是仓库自带数据。源码中的定位接口、权限处理及公开隐私说明不属于需要删除的个人记录。

后续截图须使用虚构天气、演示应用和无个人信息的图片；分享日志前检查位置、URI、设备地址和账号标识。使用 GitHub noreply 邮箱提交，避免重新引入个人邮箱。忽略规则不会清除已经提交的历史文件。

## 其他发布事项

- Launcher 自有代码为 MIT；AirPlay 接收端和修改补丁遵循上游 GPL。发布 APK 前核对对应源码、原生依赖和许可材料，保留第三方版权署名。
- 接收端当前复用固定且校验摘要的 armv7 原生库，不能称为已验证完整源码可复现构建。正式发布还需受保护的签名方案。
- 当前 CI 构建 Launcher 并运行 Lint，没有运行设备测试或覆盖接收端构建。后续可完善秘密扫描、Wrapper 校验及 Actions 版本固定。
- 功能、兼容性与性能结论以 [验证记录](VERIFICATION.md) 为准；隐私清理不构成新的电视运行测试。
